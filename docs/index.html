Your knock arrives twice.

Classic knockd destroys a knock in progress the moment a packet arrives that isn't the exact next step — a retry, a TCP retransmit, or someone else behind your NAT address. knock-daemon keeps a set of live candidates per source and adds to it, so each one resolves on its own.

The problem

One attempt per source. One stray packet ends it.

Port knocking hides a service behind a secret sequence of connection attempts on closed ports. Complete the sequence in time and the firewall opens for your IP. knockd does keep that state per source address — but only one attempt of it, and it is fragile in a way the network guarantees you will hit.

● classic knockd

One attempt, destroyed on any stray

Once a source has an attempt in flight, any packet that isn't its exact next step sets stage = -1 and kills it — and no new attempt is started, because that path only runs for a source with none. Re-send step 1 and you have not restarted; you have ended the knock.

A :41953 → A :41953 (retransmit)
attempt → stage 1 → ✗ stage = -1, discarded
the door never opens, and nothing says why
◆ knock-daemon

A set of candidates, added to

Every hit on a door's first step opens a new candidate beside the ones already running, all of them tracked per source and sharded across worker threads. A duplicate is just a second candidate. Want knockd's behaviour back? Set mode = "reset".

A :41953 → A :41953 (retransmit)
candidate 1 → stage 1  ·  candidate 2 → stage 1
either one completes the sequence — door opens
How it works

A packet's path, from the wire to the door.

Four stages, each swappable at a trait boundary — capture backend and firewall backend are chosen at build time and in config.

01 · capture

Off the wire

Pure-Rust AF_PACKET — no libpcap — or a libpcap backend. A kernel cBPF prefilter sheds non-door traffic before it reaches userspace.

02 · parse

Decode frames

One unit-tested decoder reads IPv4 / IPv6 down through VLAN and QinQ tags to the port and flags — the source of truth.

03 · match

Per-source lane

Sharded by source IP across worker threads. Each door is an ordered sequence with its own seq_timeout; an optional per-source rate limiter caps the noise.

04 · open

Grant access

The nftables backend adds the source to an allow-set with a kernel-side timeout; or the command backend runs your shell with %IP%.

Honest scope

If you can run WireGuard, run WireGuard.

A VPN authenticates. This does not. The sequence travels in cleartext on the wire, so anyone positioned to watch it can record it and replay it. Port knocking is obfuscation, and it is worth having for exactly the reasons obfuscation is worth having — no more than that.

Use a VPN when

You control both ends

WireGuard or Tailscale on both ends beats this outright, and it is not close. If the constraint that pushed you here is one you can spend your way out of, spend your way out of it instead.

Use knocking when

You can only open a socket

An appliance or embedded client that can do nothing but connect, a network where you are not allowed to install a VPN client, or one more obstacle in front of a service that already authenticates its users. What you reliably get: the port stops showing up in scans, and the auth log stops filling with credential stuffing.

One thing nobody tells you until it has already cost you an afternoon: knock-daemon only ever adds a source to an allow-set. If no rule denies that port by default, the port was open the whole time and the knock bought you nothing. Set the deny rule up first — the README gives a complete ruleset — and read SECURITY.md for what is and isn't in scope.

What ships

Built to run as a service, not a script.

◆ Two capture backends

Pure-Rust AF_PACKET with zero libpcap dependency, or a libpcap path — same tested frame decoder behind both.

◆ nftables & command

Atomic nftables allow-set with a kernel-expiring timeout, or a knockd-style shell command with %IP% substitution.

◆ Reads knockd.conf

Parses the common subset of classic knockd.conf, so most setups migrate without rewriting their doors. Directives it does not support — one_time_sequences among them — are rejected at load, not ignored, so a migration never silently drops protection you had.

◆ Sharded matching

Work fans out across threads by source IP, with an optional per-source token-bucket rate limiter.

◆ Prometheus /metrics

Knocks accepted, kernel packets and drops, and per-backend counters on a scrapeable endpoint.

◆ Runs unprivileged

A hardened systemd unit grants just CAP_NET_RAW and CAP_NET_ADMIN — no root.

◆ Self-contained binaries

Static musl and glibc tarballs plus .deb / .rpm for x86_64 and aarch64. Verified by SHA256SUMS.

◆ Memory-safe Rust

A root-adjacent network daemon with no GC. The released builds use the pure-Rust AF_PACKET backend, so they link no C capture library at all — the optional libpcap backend is the one exception, and it is not what ships. Rust 1.80+.

◆ Prove it offline

--demo replays a duplicated opening packet alongside interleaved clients, with no root and no capture; --check validates a config.

Configure

A door is an ordered sequence and a way to open it.

Plain TOML. Complete the sequence within seq_timeout and the source IP is granted access. Pick the backend that fits your firewall.

nftables backendatomic · kernel timeout

Adds the source to a named allow-set as an element the kernel expires on its own — no shell, no userspace timer.

# knockd.toml
[firewall]
backend = "nftables"

[[door]]
name        = "ssh"
sequence    = ["41953/tcp", "8271/udp", "22986/tcp"]
seq_timeout = "10s"
nft_set     = "inet filter knock_clients"
cmd_timeout = "30s"   # element lifetime
command backendknockd-compatible

Runs your shell with %IP% substituted, and can auto-undo it after cmd_timeout. Takes existing knockd recipes as they are.

# knockd.toml
[[door]]
name          = "ssh"
sequence      = ["41953/tcp", "8271/udp", "22986/tcp"]
seq_timeout   = "10s"
open_command  = "nft add element … { %IP% }"
close_command = "nft delete element … { %IP% }"
cmd_timeout   = "30s"

Those ports are not in ascending order, and yours should not be either. An ordinary ascending port scan walks 7000, 8000, 9000 in exactly that order and completes a door built on them inside seq_timeout, knowing nothing about your config — in reset mode as much as in tolerant.
